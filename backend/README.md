# Сервер (backend)

Сервер Beautybook (до 2.4.0 — Nailapp) на Cloudflare Workers с базой D1. Он:
- хранит аккаунты мастеров: регистрация с анкетой (направление, номер Kaspi), вход, смена и сброс пароля;
- ведёт подписки (7 бесплатных дней, тариф «Про» на месяц или год) и чат мастера с администратором;
- присылает уведомления администратору (с 2.5.0): сообщения мастеров, новые мастера, «Я оплатил(а)», утренняя сводка по подпискам;
- считает записи и заявки мастеров по месяцам для администратора;
- принимает заявки клиентов;
- присылает мастеру уведомления;
- хранит свободное время для страницы клиентов и записи для личных ссылок;
- хранит облачную копию записей и фото.

Адрес: https://kae-zapis-api.kae-zapis.workers.dev. Сайт, который к нему обращается, лежит в папке [frontend](../frontend/README.md).

| Файл | Что это |
|---|---|
| `src/index.js` | Все адреса сервера (`/api/…`) |
| `src/push.js` | Уведомления Web Push: подпись VAPID и шифрование, без сторонних библиотек |
| `src/webauthn.js` | Вход по Face ID (WebAuthn): разбор CBOR, ключи P-256 и RSA, проверка регистрации и подписи, без сторонних библиотек |
| `migrations/` | Устройство базы D1: по файлу на каждое изменение |
| `wrangler.toml` | Настройки Cloudflare: имя сервера и база |
| `tests/` | Тесты уведомлений и входа по Face ID (`soft-authenticator.mjs` — программный «телефон»), проверка сервера целиком: аккаунты, данные мастеров не смешиваются (`api.integration.mjs`) |

Правила свободного времени и проверки заявки сервер берёт из `../frontend/logic.js`. Это тот же файл, что у сайта, поэтому правила не расходятся.

## Адреса

- **Для всех:**
  - `GET /api/okna?m=<ссылка мастера>` — свободное время мастера (без `m` — Арай);
  - `POST /api/requests?m=<ссылка мастера>` — заявка клиента;
  - `GET /api/bookings/:ссылка` — запись клиента по личной ссылке;
  - `POST /api/register` — регистрация мастера: имя, номер, пароль, `specialty` (направление) и `kaspi` (номер для счёта Kaspi) обязательны; без поля `specialty` (приложение до 2.4.0) — 400 «Обновите приложение»;
  - `POST /api/login` — вход мастера (номер и пароль);
  - `GET /api/contact` — WhatsApp администратора для «Забыли пароль?»;
  - `POST /api/errors` — ошибка со страницы (`frontend/errors.js`) в журнал;
  - `POST /api/pair` — вход по коду доступа, как до 2.0.0. Работает, только пока Арай не оформила аккаунт.
- **Только для телефона мастера** (по ключу устройства; каждый мастер видит только своё):
  - аккаунт: `GET /api/account` (с `specialty`, `kaspi` и `chatUnread` — непрочитанные сообщения администратора), оформление прежнего аккаунта `POST /api/account/claim`, анкета `PUT /api/account/profile` `{specialty, kaspi}`, смена пароля `PUT /api/account/password`, выход `DELETE /api/account/session`;
  - чат с администратором: `GET /api/chat` (сообщения администратора становятся прочитанными), `POST /api/chat` `{text}` — до 2 000 знаков, не больше 60 сообщений в час; администратору — уведомление. Анкета и чат работают и после окончания подписки;
  - «Я оплатил(а)»: `POST /api/account/paid` — администратору уведомление с номером Kaspi мастера (не чаще 3 раз в час; потом `notified: false`); работает и после окончания подписки;
  - числа записей для администратора: `PUT /api/stats` `{months: {'YYYY-MM': {total, link, clients}}, clients}` — без имён и телефонов (`L.statsPayload`);
  - расписание;
  - заявки: список, подтверждение, отклонение;
  - личные ссылки;
  - уведомления;
  - копия и фото.
- **Для администратора** (заголовок `Authorization: Admin <код в base64url>`):
  - `GET /api/admin/masters` — все мастера: адрес, 2ГИС и Instagram из расписания, направление, номер Kaspi, клиентов в базе, непрочитанные сообщения (`unread`), записи по месяцам за год (`stats[YYYY-MM]`: `total`, `link`, `manual`, `clients` — от приложения; `sent`, `confirmed` — заявки по ссылке, считает сервер), объём данных (`storage`), размер всей базы (`size`) и снимок нагрузки за сутки (`usage`, см. «Проверка»);
  - `POST /api/admin/masters/:id/password` — новый пароль мастеру (его телефон выходит из аккаунта);
  - `PUT /api/admin/contact` — свой WhatsApp;
  - `POST /api/admin/masters/:id/subscription` — подписка мастера: `{action: 'extend', plan: 'month' | 'year'}` (оплата получена: +месяц или +12 месяцев, в период пишутся `plan` и сумма `amount` по `L.TARIFF`), `'undo'` (отменить последнюю оплату), `'unlimited'` с `value` true/false, `'until'` с `value` YYYY-MM-DD;
  - чат: `GET /api/admin/chats` — переписки (последнее сообщение, непрочитанные), `GET /api/admin/chats/:id` — сообщения (сообщения мастера становятся прочитанными), `POST /api/admin/chats/:id` `{text}` — ответ; мастеру уходит уведомление (`kind: 'chat'`, открывает чат);
  - уведомления администратору: `GET /api/admin/push` — ключ сервера (`key`) и устройства (`devices`), `PUT /api/admin/push` `{subscription, name}` — включить на устройстве, `DELETE /api/admin/push` `{endpoint}` — выключить, `POST /api/admin/push/test` — пробное (`sent` — на сколько устройств ушло);
  - вход по Face ID (WebAuthn): `GET /api/admin/passkeys`, `POST /api/admin/passkey/options` и `POST /api/admin/passkeys` — включить на устройстве, `DELETE /api/admin/passkeys/:id` — убрать. Без кода: `POST /api/admin/passkey/login-options` и `POST /api/admin/passkey/login` → сеанс на 12 часов (`Authorization: Session <сеанс>` вместо кода).

## Подписки

- `masters.paid_until` — последний день доступа (по времени Алматы), `masters.unlimited` — бессрочно; периоды — таблица `subscriptions` (`trial` — бесплатные дни после регистрации: с 2.4.0 — 7 дней, `L.trialPeriod`, раньше — месяц; `paid` — оплата, отмеченная администратором, с `plan` и `amount`; `manual` — дата вручную). Миграции 0008 и 0009.
- Подписка закончилась: запросы телефона мастера, кроме аккаунта (`/api/account…`), получают 402 «Подписка закончилась — продлите её у администратора»; `GET /api/okna` отвечает `paused: true` без свободного времени, заявки — 503. Личные ссылки клиентов работают.

## Анкета, чат и статистика (2.4.0, миграция 0009)

- `masters.specialty` (видят клиенты в расписании и администратор), `masters.kaspi_phone` (только администратор), `masters.clients` (сколько клиентов в базе мастера).
- `messages (id, master_id, author master|admin, text, created, seen)` — переписка мастера с администратором.
- `master_stats (master_id, month, total, link, clients)` — что прислало приложение мастера; `link` не больше `total`.
- `request_stats (master_id, month, sent, confirmed)` — заявки по ссылке: отправлены клиентами и подтверждены мастером, по месяцу записи.
- В расписании для клиентов (`L.cleanSchedule`) — `instagram` (ник), `specialty` (текст без тегов, до 40 знаков) и `theme` (тема мастера, иначе `plum`); их же отдаёт `GET /api/bookings/:ссылка` в `master`.

## Уведомления администратору (2.5.0, миграция 0010)

- Таблица `admin_push (endpoint, value, name, created)` — подписки устройств администратора; подписку, которую служба уведомлений больше не знает (404/410), сервер удаляет сам.
- События: сообщение мастера в чате (`kind: 'chat'`, `./?open=chat&m=<id>`), регистрация мастера (`master`, `./?open=master&m=<id>`), «Я оплатил(а)» (`paid`, карточка мастера), утренняя сводка (`subs`, `./?open=subs`) — у кого подписка кончается сегодня или завтра и у кого закончилась вчера; если таких нет, сводка не приходит.
- Сводку запускает Cloudflare по расписанию: `[triggers] crons = ["0 4 * * *"]` в `wrangler.toml` (04:00 UTC = 09:00 по Алматы), обработчик `scheduled` в `src/index.js`. Проверка на компьютере: `wrangler dev --test-scheduled`, затем открыть `http://127.0.0.1:8787/__scheduled?cron=0+4+*+*+*`.

## Аккаунты и пароли

- Пароль на сервер не приходит. Телефон «растягивает» его функцией PBKDF2-SHA256 (200 000 шагов, соль — номер телефона) и отправляет результат. Сервер хранит SHA-256 этого результата со своей случайной солью.
- Вход выдаёт телефону ключ устройства. В базе лежит только хэш ключа. Один мастер — один телефон: вход на новом отключает прежний.
- Попытки ограничены: 5 регистраций в час с одного адреса, 10 неверных входов в час с адреса и 20 — на один номер, 5 неверных кодов администратора в час.
- Данные прежнего мастера (до 2.0.0) принадлежат аккаунту `legacy` со ссылкой `aray`. Миграция `0004_masters.sql` создала его и привязала к нему всё, что было в базе.
- Расписание мастера проходит через `L.cleanSchedule` при сохранении и при выдаче клиентам: даты, время и числа — строго своего вида, строки обрезаны, лишние поля отброшены. Иначе мастер мог бы вставить в свою страницу чужой код.

## Проверка «всё ли в порядке»

`monitor.mjs` читает: открываются ли сервер и сайт, нагрузка на базу против лимитов бесплатного тарифа (предупреждение с 50%, тревога с 80%), мастера, фото, новые ошибки в журнале. Пишет в базу одно — снимок нагрузки за сутки в `config.usage` (`at`, `size`, `requests`, `rowsWritten`, `rowsRead`): его показывают шкалы в разделе «Сервер» у администратора (сам Worker своих суточных цифр не знает). Запуск из папки `backend`: `~/.local/node/bin/node monitor.mjs`. В конце печатает «ИТОГ: OK | WARN | ALERT» и текст уведомления, если есть о чём сообщить (одно и то же — не чаще раза в сутки). История проверок — `../.claude/monitor-log.md` (в git не попадает). Три раза в день его запускает задача Claude «Nailapp: проверка сервера и ссылок» и при проблеме присылает уведомление (текст начинается с «Beautybook:»).

## Журнал ошибок

Таблица `errors` (миграция 0005): сбои сервера (`source = server`, адрес запроса без id и ссылок) и ошибки со страниц (`app`, `okna`, `admin`). Личных данных нет. Хранится 14 дней, не больше 300 записей в час; со страниц — не больше 20 сообщений в час с одного адреса. Посмотреть последние:

`~/.local/node/bin/node ~/.local/node/bin/wrangler d1 execute kae-zapis --remote --command "SELECT at, source, place, message FROM errors ORDER BY id DESC LIMIT 20"`

## Хранилище и лимиты

- Фото и копии данных лежат в D1 (строка не больше 2 МБ): фото — до 1,9 МБ, копия — до 1,9 МБ, у мастера хранятся 30 последних копий. Лимитов на число фото у мастера пока нет.
- Бесплатный тариф Cloudflare: 100 000 запросов к серверу в сутки, база до 500 МБ, 100 000 записанных строк и 5 млн прочитанных строк в сутки. Счётчики обнуляются в 00:00 UTC (05:00 по Алматы).

## Команды

Все команды выполняются из папки `backend`. Node.js и wrangler лежат в `~/.local/node`, поэтому команды длинные.

| Что сделать | Команда |
|---|---|
| Выложить сервер | `~/.local/node/bin/node ~/.local/node/bin/wrangler deploy` |
| Обновить базу, если в `migrations/` появился новый файл (до выкладки) | `~/.local/node/bin/node ~/.local/node/bin/wrangler d1 migrations apply kae-zapis --remote` |
| Задать или сменить код администратора | `~/.local/node/bin/node ~/.local/node/bin/wrangler secret put ADMIN_CODE` |
| Сменить код доступа (пока не задан `ADMIN_CODE`, он же — код администратора) | `~/.local/node/bin/node ~/.local/node/bin/wrangler secret put ACCESS_CODE` |
| Тесты | `~/.local/node/bin/node --test "tests/*.test.js"` |
| Проверка сервера целиком (при запущенном `wrangler dev`) | `~/.local/node/bin/node tests/api.integration.mjs` |
| Сервер на компьютере (http://127.0.0.1:8787) | `~/.local/node/bin/node ~/.local/node/bin/wrangler dev` |

Для сервера на компьютере есть своя база и тестовый код доступа в `.dev.vars`. В git они не попадают.
